# 问题诊断决策树 (Problem Diagnosis Decision Tree)

> 使用说明: 当客户描述了一个模糊的问题("系统很慢"/"IT成本太高"/"数据不好用"), 使用这个决策树快速找到根因方向和对应的解决路径。不要直接从问题跳到解决方案。

---

## 决策树总图

```
客户说: "[模糊的问题]"
    │
    ├── 问题可以量化吗?
    │   ├── 可以 → 进入 [量化诊断路径]
    │   └── 不行 → 先做 [问题澄清] (用5W1H)
    │
    ├── 问题的本质是什么? (MECE五维分解) → 见下方分类树
    │
    └── 快速定位 → 进入对应的workflow
```

---

## 分类一: "系统太慢了" / "性能不行"

```
"系统太慢了"
    │
    ├── 什么时候慢?
    │   ├── 一直慢 → 
    │   │   ├── 所有人慢? → 基础设施/架构问题 → workflow 02-03 (IT诊断)
    │   │   └── 某些人慢? → 网络/地域/权限问题
    │   │
    │   └── 有时候慢(间歇性) →
    │       ├── 高峰期慢? → 容量不足 → 扩容 or 架构优化
    │       ├── 特定操作慢? → 某个API/查询/数据库 → 定位到具体代码
    │       └── 随机慢? → 外部依赖/GC/资源争抢 → 可观测性排查
    │
    ├── 慢在哪里?
    │   ├── 前端渲染慢? → 前端性能优化 (减少Bundle/懒加载)
    │   ├── API响应慢? → 后端逻辑/数据库查询/依赖服务
    │   ├── 数据库查询慢? → 索引/查询优化/数据量
    │   └── 网络传输慢? → CDN/带宽/数据压缩
    │
    └── 和什么比"慢"?
        ├── 比去年慢了? → 数据量增长/用户增长/技术债累积
        ├── 比竞品慢? → 架构差距/技术选型差距
        └── 比预期慢? → 需求vs实际/基准测试
```

## 分类二: "IT成本太高了"

```
"IT成本太高了"
    │
    ├── 哪一类成本高?
    │   ├── 人太多? → 组织诊断 → workflow 02-03
    │   │   ├── 人数合理但效率低? → 自动化/工具/流程
    │   │   └── 外包占比太高? → 内包/供应商重新谈判
    │   │
    │   ├── 基础设施/云成本? → FinOps评估 → workflow 05-03
    │   │   ├── 没有标签/不知道钱花在哪? → Phase 1: Inform
    │   │   ├── 知道花在哪但不知道怎么优化? → Phase 2: Optimize
    │   │   └── 优化过了还是贵? → 架构优化/供应商重新谈判
    │   │
    │   ├── 软件许可证? → 许可证审计+优化
    │   │   ├── 有闲置许可证吗? → 回收
    │   │   ├── 高级功能没人用? → 降级
    │   │   └── 合同快到期? → 重新谈判
    │   │
    │   ├── 项目/供应商? → 供应商管理 → workflow 07-02
    │   │   ├── 供应商报价虚高? → 基准比价+谈判
    │   │   ├── 变更请求费用失控? → 变更管理流程
    │   │   └── SLA溢价但服务差? → 降级SLA或换供应商
    │   │
    │   └── 不知道哪类—所有都高? → 全面IT成本诊断 → workflow 05-01
    │
    ├── 和什么比"高"?
    │   ├── 比去年高了? → 增长合理性(用户/业务增长?)
    │   ├── 比行业基准高? → 对标分析 → references/基准数据与行业指标.md
    │   └── 比预算高了? → 预算执行问题/隐性成本
    │
    └── 这是在什么背景下?
        ├── IT投资增加但业务价值没增加? → ROI问题 → workflow 05-02
        ├── IT投资增加是战略需要(数字化转型)? → 确保有商业论证
        └── IT投资减少(降本压力)? → 成本优化 → workflow 05-03
```

## 分类三: "数据不好用" / "数据质量差"

```
"数据不好用"
    │
    ├── 什么样的"不好用"?
    │   ├── 找不到数据? → 数据资产不可发现 → workflow 03-05 (数据战略)
    │   │   └── 需要数据目录(Data Catalog)+元数据管理
    │   │
    │   ├── 找到了但不知道什么意思? → 数据字典/元数据缺失
    │   │
    │   ├── 数据不准? → 数据质量问题
    │   │   ├── 哪些数据不准? → 清单
    │   │   ├── 不准的原因? → 
    │   │   │   ├── 源头就错了? → 录入/采集问题
    │   │   │   ├── 各系统数据不一样? → 主数据不一致 → MDM
    │   │   │   ├── 数据过时了? → 时效性问题
    │   │   │   └── 加工过程出错? → ETL/计算逻辑错误
    │   │   └── 进入数据质量改进流程 → workflow 03-05
    │   │
    │   ├── 数据在不同的地方/不互联? → 数据孤岛
    │   │   └── 数据集成/数据平台架构 → workflow 03-05
    │   │
    │   └── 数据有但是不知道怎么用(做分析/AI)? → 数据分析能力 → workflow 03-05
    │
    └── 谁在抱怨?
        ├── 业务人员(需要数据做决策) → 自助分析/数据民主化
        ├── 数据科学家(需要数据训练模型) → 数据就绪度+特征工程
        └── 监管/合规(数据不合规) → 数据治理+合规
```

## 分类四: "数字化/IT不支撑业务"

```
"IT不支撑业务"
    │
    ├── 什么意思?
    │   ├── IT响应太慢? (要一个报表2个月)
    │   │   ├── 需求太多? → 需求优先级+产品化运作
    │   │   ├── IT产能不够? → 资源/效率/外包
    │   │   └── 流程太繁琐? → 敏捷转型/DevOps
    │   │
    │   ├── IT做的东西业务不需要? (做完了没人用)
    │   │   ├── 需求没对齐? → 产品管理/BA能力
    │   │   ├── 沟通出问题? → IT与业务协作机制
    │   │   └── 没有早期业务参与? → 让业务从一开始就参与
    │   │
    │   ├── IT不理解业务? 
    │   │   └── IT组织设计问题 → workflow 06-02 (IT组织设计)
    │   │
    │   ├── IT技术太旧, 跟不上业务需求?
    │   │   └── 架构现代化 → workflow 03-03 (企业架构)
    │   │
    │   └── IT的战略方向和业务方向不一致?
    │       └── IT战略重新对齐 → workflow 03-01 (IT战略规划)
    │
    └── 这是感受还是事实?
        ├── 感受(但广泛存在) → 需要客观诊断(workflow 02-03)来找真实差距
        └── 事实(有数据支撑) → 搞清楚根因再制定方案
```

## 分类五: "安全担忧" / "怕出事"

```
"我们对安全没信心"
    │
    ├── 为什么没信心?
    │   ├── 出过事? → 什么类型?
    │   │   ├── 数据泄露 → 数据安全+DLP
    │   │   ├── 勒索软件 → 备份+端点安全+安全意识
    │   │   ├── 钓鱼成功 → 安全意识培训+钓鱼测试
    │   │   └── 内部人员 → 权限管理+审计
    │   │
    │   ├── 没出过事但觉得不安全?
    │   │   ├── 不知道有什么漏洞? → 渗透测试+漏洞扫描
    │   │   ├── 合规要求变严了? → 等保/ISO27001/SOC2
    │   │   ├── 看到同行出事了? → 风险评估+对标
    │   │   └── 监管要检查了? → 合规评估 → workflow 03-06
    │   │
    │   ├── 供应商/第三方风险?
    │   │   └── 供应链安全 → workflow 03-06
    │   │
    │   └── OT(工控)安全?(制造业/能源)
    │       └── OT/IT安全融合 → workflow 03-06
    │
    └── 进入安全战略workflow → workflow 03-06
```

## 分类六: "想搞AI但不知道怎么开始"

```
"我们要搞AI" / "AI能帮我们做什么"
    │
    ├── 为什么想搞AI?
    │   ├── 老板说了要搞(AI旅游) → 先做AI素养+用例研讨会
    │   ├── 竞品在搞 → 竞品分析+差异化AI战略
    │   ├── 确实有业务问题适合AI → ✅ 正确的出发点
    │   └── 不知道, 就是觉得该搞 → 从AI成熟度评估开始
    │
    ├── 想用AI解决什么?
    │   ├── 有明确问题 → 进入AI用例评估 → workflow 03-02
    │   ├── 说不清楚 → AI启发式研讨会(Discovery Workshop)
    │   └── "所有的都可以搞" → 帮助聚焦, 选1-2个最高价值场景
    │
    ├── 数据准备好了吗?
    │   ├── 有数据且质量好 → ✅ 可以开始了
    │   ├── 有数据但质量差 → 先做数据治理 → workflow 03-05
    │   ├── 没有数据(需要的场景没数据) → 先建立数据采集
    │   └── 不知道有没有 → 数据盘点
    │
    ├── 技术能力准备好了吗?
    │   ├── 有AI/ML团队 → ✅ 
    │   ├── 没有但有云平台 → 可尝试云AI服务(低代码)
    │   ├── 什么都没有 → 从简单场景+外部支持开始
    │   └── 团队想学但不知道怎么学 → AI素养培训 → references/AI与商业转型深度框架.md
    │
    └── 进入AI转型战略 → workflow 03-02
```

## 分类七: "供应商问题"

```
"供应商有问题"
    │
    ├── 什么问题?
    │   ├── 想选供应商但不知道怎么选?
    │   │   └── → workflow 04-02 (RFP全流程) + 04-03 (供应商评估)
    │   │
    │   ├── 供应商表现不好?
    │   │   ├── 交付质量差? → 供应商绩效管理 → workflow 07-02
    │   │   ├── 交付延迟? → 合同管理+升级
    │   │   ├── 频繁换人? → 合同条款执行
    │   │   └── 服务态度差? → 季度业务评审(QBR) + 升级
    │   │
    │   ├── 供应商费用不断涨?
    │   │   ├── 合理涨价(成本增加)? → 协商封顶
    │   │   ├── 不合理涨价(锁定效应)? → 引入竞争/评估替代
    │   │   └── 隐性费用不断冒出? → 合同审查+每月费用审查
    │   │
    │   ├── 想换供应商?
    │   │   └── → workflow 07-02 (供应商退出管理)
    │   │
    │   ├── 供应商要被收购/倒闭了?
    │   │   └── 立即做风险评估+备选方案+数据备份
    │   │
    │   └── M&A/尽职调查需要评估技术?
    │       └── → workflow 04-01 (技术尽调)
```

## 使用流程

1. **听到问题后**, 先在白板上/脑里画出"这是哪一类问题?"
2. **追问3-5个澄清问题**, 缩小问题范围
3. **沿着决策树找到对应的最深层节点**
4. **进入对应的workflow**, 按分步操作执行
5. **如果问题跨多个分类**(多数真实问题是跨领域的), 按优先级并行推进

---

## 关键提醒

- 决策树是指南, 不是铁律 — 真实客户问题常常是"上面6个问题都有"
- 听到第一个问题不要直接给方案 — 先问"你能给我一个具体的例子吗?"
- 如果客户说的和决策树都对不上 — 可能是问题还没有被正确表述, 回到5W1H重新澄清
- 最危险的是客户说"系统慢"然后你开始做性能优化 — 其实他说的"慢"是指"需求响应慢"(流程问题, 不是技术问题)
