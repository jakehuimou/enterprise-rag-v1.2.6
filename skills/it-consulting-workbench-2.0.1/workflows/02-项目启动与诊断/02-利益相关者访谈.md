# 02 — 利益相关者访谈

## 目标
通过结构化访谈，获取不同视角的IT现状认知、痛点、期望和隐性信息。访谈是咨询诊断阶段最重要的信息获取手段——比任何文档都真实。

## 前置条件
- 项目已启动，客户已通知各利益相关者配合访谈
- 已了解被访者的角色/职级/在项目中的位置
- 访谈时间已确认(每人45-60分钟)

## 输入物
- 利益相关者名单与角色
- 项目章程
- 客户背景材料(如有)

---

## 操作步骤

### Step 1: 制定访谈计划 — 访谈谁，按什么顺序

**访谈顺序原则: 从外到内，从上到下**

```
Wave 1: 高管层 (CEO/CIO/CFO/BU Head) — 获取战略视角
  → 目的: 理解业务战略、高层痛点、决策逻辑、政治格局
  → 先访谈Sponsor，确保高层支持方向

Wave 2: 中层管理者 (IT Director/App Owner/PMO Head) — 获取运营视角
  → 目的: 理解现状细节、流程瓶颈、团队动态、历史项目成败

Wave 3: 一线执行者 (工程师/运维/业务分析师) — 获取真相视角
  → 目的: 验证上层信息、发现被掩盖的问题、获取技术细节

Wave 4: 外部视角 (关键供应商/合作伙伴) — 获取第三方视角
  → 目的: 了解合作关系、供应商眼中的客户能力、外部依赖风险
```

**访谈前必做: 个人背景研究 (每人5-10分钟)**

```
每个被访者，你至少要知道:
□ 在公司的年限和晋升轨迹
□ 最近负责的重大项目(成功或失败)
□ 在LinkedIn/脉脉上的发言和关注点
□ 可能的前东家/行业背景带来的"path dependency"
□ 此人和谁关系好/有矛盾(从其他访谈中获取)
```

### Step 2: 按角色设计访谈问题

**CEO/总裁级 (45min)**

```
目标: 理解战略意图、优先级、对IT的真实期望

1. (5min) 暖场: "感谢您抽出时间。我们先简单聊聊——您觉得过去两年公司最大的变化是什么?"
2. (15min) 战略: "如果往前看3年，您觉得公司在市场中的位置需要发生什么根本性改变?这些改变对技术/数字化有什么要求?"
3. (10min) 痛点: "从您的角度，目前IT/技术方面最让您睡不着觉的是什么?如果用1-10打分，您对IT支撑业务的能力打几分?"
4. (10min) 期望: "假设18个月后我们回头看今天，您希望看到IT/数字化方面发生了哪些变化?怎么衡量成功了?"
5. (5min) 收尾: "有什么我没问到但您觉得我应该知道的事情?"

关键: CEO不说"IT"，他们说"业务"。>不要纠正他们的术语，而是翻译。
如果CEO说"系统太慢"，翻译成: 市场响应速度不够。
```

**CIO/CTO (60min)**

```
目标: 获取IT全貌、技术决策逻辑、团队真实状态

1. (5min) "您过去一年最大的精力花在了什么地方?"
   → 答案可能是: 维稳/救火 → IT成熟度低; 新项目/创新 → IT成熟度高
2. (10min) IT现状全景: "如果用一张图描述当前的IT全景——核心系统、关键依赖、最大瓶颈——会是什么样?"
3. (15min) 痛点深挖(用5维框架):
   技术: "最大的技术债务在哪里?如果明天有一个无限预算和0风险的改造窗口，你会先改什么?"
   流程: "从业务提需求到IT交付，最慢的环节是什么?"
   组织: "你最想招但一直招不到的是什么人?你最希望团队提升什么能力?"
   数据: "如果你现在要做个公司级数据分析，数据获取要多久?"
   财务: "IT预算里最大的'黑洞'在哪里?什么钱花了但没看到效果?"
4. (10min) 供应商生态: "你最满意的供应商是哪个?最头疼的?为什么?"
5. (10min) 历史: "过去两年最大的IT项目是哪个?结果如何?如果重来一次会怎么做?"
6. (5min) 创新: "你有什么想做但一直没推进的想法?"
7. (5min) "有什么其他人不会告诉我但你希望我知道的?"

关键: CIO可能"美化"现状。交叉验证: 问他能提供什么数据或报告("有系统可用性周报吗?我可以看看吗?")
```

**CFO (30min)**

```
目标: 获取财务视角、预算压力、投资回报预期

1. "从财务角度看，IT在您眼中是什么样的角色——成本中心、效率引擎、还是增长驱动?"
2. "IT预算占收入的___%。这个比例您觉得合适吗?过去三年的趋势是?"
3. "您怎么判断一个IT项目的投资是否合理?有没有做过事后ROI评估?"
4. "如果明年要砍IT预算10%，您觉得哪里最容易被砍?哪里绝对不能碰?"
5. "IT的费用里，您觉得'看不到效果的支出'占多少?"
```

**业务VP/BU Head (45min)**

```
目标: 获取IT的真正用户声音——这部分往往和IT部门的说法不一致

1. "您团队的业绩目标是什么?IT在支撑这些目标上做得好/不好的地方?"
2. "如果让您用三个词形容公司IT部门，您会用哪三个词?"
3. "上次IT帮您解决了一个重大业务问题，是什么时候?怎么解决的?"
4. "您的团队有没有绕过IT自己买SaaS/找外包?为什么?"
   → 这是关键信号。大量影子IT说明IT部门被视为瓶颈
5. "如果您可以给CIO提一个建议，会是什么?"
```

**一线工程师 (30min)**

```
目标: 获取技术真相、文化感知、最真实的痛点

1. "你每天的工作流是怎样的?哪些环节最花费时间但你觉得本可以优化?"
2. "上次上线一个功能，从写完代码到真正运行花了多久?"
3. "技术栈里哪些部分让你觉得'这不能再这样下去了'?"
4. "你觉得团队的技术决策是怎么做出的?你有发言权吗?"
5. "公司有没有鼓励技术学习和创新?你觉得在这是在学习还是在'吃老本'?"
6. "如果让你给新来的CTO一个建议，会是什么?"

关键: 一线不设防，可能透露CIO不愿说的事。承诺匿名，且一定做到。
```

### Step 3: 访谈中的核心技巧

**技巧1: 80/20倾听法则**
- 你说的话 < 20%
- 沉默是武器: 回答结束后默数3秒再说话，对方往往会补充最重要的信息
- "嗯""然后呢?""能多说说吗?" 比任何准备好的问题都有效

**技巧2: 注意到情绪信号**
```
当被访者...
  突然语速变快  → 这是他们真正在意的事(正面或负面)
  突然停顿犹豫  → 这里有政治敏感信息或不愿说的事
  反复强调某件事 → 这是他们想让你带走的核心信息
  使用模糊措辞   → "我们需要改进流程" → 追问"具体哪个流程的哪个环节?"
  提到具体人名   → 注意记录关系动态和权力格局
```

**技巧3: 三角验证**
同一个事实，问3个不同角色:
```
你问CIO: "ERP系统运行得怎么样?"
  → "整体稳定，小问题都及时处理了"

你问业务VP: "ERP好用吗?"
  → "月底结账要通宵，IT说没法优化"

你问财务操作员: "ERP结账流程顺利吗?"
  → "每个月都要手动导Excel再加工，系统报表完全不准确"

真相: ERP功能勉强可用，但月底结账依赖大量手工补偿操作
```

### Step 4: 访谈后2小时内的合成

**立即记录(记忆最鲜活):**
```
访谈合成卡:

被访者: [姓名/职位]  日期: [date]  时长: [min]
访谈氛围: [开放坦诚/谨慎保守/消极抗拒/...]

Top 3 关键信息:
1. [最有价值的发现]
2. [...]
3. [...]

直接引语 (最有力的证据):
"......" — [谁说的]

情绪信号:
- [兴奋/自豪/...] 关于: [话题]
- [沮丧/担忧/...] 关于: [话题]
- [回避/闪烁其词] 关于: [话题]

与其他访谈的一致/矛盾:
✓ 一致: [话题] → [谁和谁说的吻合]
✗ 矛盾: [话题] → [A说X但B说Y] → 需要进一步验证

对我的假设的影响:
- 证实: [哪个假设被证实了]
- 证伪: [哪个假设被推翻了]
- 新假设: [发现了什么新的方向]

下一步:
- [需要找谁验证]
- [需要获取什么数据]
```

## 交付物

- 每位被访者的访谈合成卡
- 跨访谈交叉分析(矛盾点地图)
- 更新后的假设和验证状态

## 质量检查

- [ ] 覆盖了所有关键利益相关者角色
- [ ] CEO/CIO/至少1位业务VP/至少2位一线人员已访谈
- [ ] 每位被访者的合成卡在访谈后2小时内完成
- [ ] 关键发现已三角验证(至少2个来源交叉确认)
- [ ] 识别了矛盾点并有后续验证计划
- [ ] 访谈为诊断报告的每个核心发现提供了supporting evidence

## 常见陷阱

| 陷阱 | 正确做法 |
|------|---------|
| 只访谈到IT部门的人 | 没有业务部门的视角，诊断报告必然失偏 |
| 按统一问题清单机械提问 | 准备好问题但灵活应对——最好的问题往往来自对方的回答 |
| 在访谈中开始给建议 | 访谈阶段你的角色是"学生"不是"专家"。给建议会关闭对方的信息流 |
| 偏信第一个告诉你某件事的人 | 永远三角验证。第一个信息提供者可能因为职位/立场/利益而在引导你的结论 |
| 笔记记太详细导致跟不上对话 | 关键词+情绪信号+直接引语。不是速记员，是解读者 |
