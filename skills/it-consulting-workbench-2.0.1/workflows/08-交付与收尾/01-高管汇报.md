# 高管汇报 (Executive & Board Presentation)

## 目标

向董事会/CEO/SteerCo等高管层进行有影响力的汇报, 推动决策, 展示进展, 管理预期。

---

## 前置条件
- 汇报目的明确(请求决策/展示进展/风险预警/项目收尾)
- 了解听众(谁参加/他们关心什么/有什么预设)
- 数据和分析已准备完毕

## 输入物
- 项目进展/成果数据
- 财务分析(商业论证/ROI/TCO)
- 风险与问题清单
- 决策请求列表

---

## 操作步骤

### 第一步: 汇报策划 — 了解你的听众

#### 1.1 高管听众分析

| 角色 | 关心什么 | 怕什么 | 汇报中怎么应对 |
|------|---------|--------|-------------|
| CEO | 战略对齐/竞争力/增长/股价 | 落后于竞争对手/错过趋势/大投资没结果 | 从行业趋势切入, 讲战略逻辑, 给信心 |
| CFO | 钱/回报/风险/现金流 | 投资打水漂/预算失控/说不清ROI | 数字要扎实, 敏感性分析准备好, 替代方案说清楚 |
| COO | 运营影响/效率/稳定性 | 业务中断/效率下降/团队不稳定 | 讲清楚对运营的影响和过渡方案 |
| 独立董事 | 治理/合规/风险 | 渎职风险/不知情/被问责 | 展示治理架构和风险管理, 证明尽职 |
| 业务VP | 对自己部门的影响 | 失控/被取代/增加负担 | 提前1on1沟通, 把TA的顾虑纳入方案 |

#### 1.2 汇报前政治地图

在汇报前, 必须搞清楚:
- 谁支持? (确保TA在会议上公开支持)
- 谁反对? (提前1on1了解顾虑, 修改方案或准备回应)
- 谁是摇摆票? (会前单独沟通, 争取支持)
- 谁是决策者? (不一定职位最高的人)

---

### 第二步: 汇报结构设计 (SCQA框架)

#### 2.1 SCQA叙事框架

麦肯锡经典叙事结构:

**S — Situation (情境)**
"我们所在的行业正在经历XXX..."
(先说大家都知道的事实, 建立共同认知基础)

**C — Complication (冲突)**
"但是, 我们面临XXX挑战/威胁/机会..."
(为什么现状不行了? 外部发生了什么变化? 内部有什么问题?)

**Q — Question (问题)**
"那么, 我们应该怎么做?"
(自然而然地引出需要讨论和决策的问题)

**A — Answer (答案)**
"我们的建议是XXX"
(给出你的方案, 支撑以数据和逻辑)

#### 2.2 执行摘要先行 (BLUF: Bottom Line Up Front)

高管最讨厌: 听了15分钟还不知道你要说什么

```
每个高管汇报的第一个30秒:
"各位, 我今天要汇报的是XXX项目。
当前状态是[On Track/At Risk]。
我请求董事会批准[1-2句话的决策请求]。
如果批准, 预期[核心收益, 1个数字]。
我今天会用[XX]分钟讲完, 留[XX]分钟给大家提问。"

然后再说背景、逻辑、数据。
```

### 第三步: Slide-by-Slide构建

*(详细模板见 templates/董事会汇报模板.md)*

#### 3.1 关键页面设计原则

**每页一个核心信息:**
```
❌ Page Title: "项目进展情况"            (标题是"话题")
✅ Page Title: "项目按计划推进, 三个核心里程碑均提前完成" (标题就是"结论")
```

**每页3秒测试**: 3秒扫一眼就该知道这一页在说什么
- 关键数字/结论要大字突出
- 图表有清晰的标注
- 不重要的信息放附录

**每页讲1-2分钟原则**: 
- 不要在Slide 5上停留8分钟解释
- 如果某个话题需要深入, 放到附录, 被问到再打开

#### 3.2 图表使用

| 要表达什么 | 用什么图 |
|-----------|---------|
| 趋势 | 折线图 |
| 对比 | 柱状图/条形图 |
| 构成/占比 | 堆叠柱状图/饼图(最多5块)/瀑布图 |
| 相关性 | 散点图 |
| 流程/路线图 | 时间轴/甘特图 |
| 分布 | 直方图/箱线图 |

**图表铁律:**
- 每个图表只讲一件事
- 标注所有轴/单位/数据来源
- 关键数据点突出(颜色/箭头/标注)
- 3D图表从来不用(扭曲数据)

### 第四步: 高风险场景处理

#### 4.1 当你需要汇报坏消息时

```
坏消息汇报框架:

1. [Headline] — 直接说问题
   "项目进度延迟了6周, 预算预计超支15%"

2. [Root Cause] — 根本原因(不要找借口)
   "根本原因是数据迁移的复杂度超出我们的初始估计: 
    我们原以为5个源系统, 实际是12个, 且数据质量比预想的差"

3. [Impact] — 影响是什么
   "这意味着上线时间从Q3推迟到Q4, 总成本从$5M增加到$5.75M"

4. [What We've Done] — 我们已经做了什么
   "我们已经:
    - 增加了2名数据工程师
    - 调整了迁移策略(分批替代一次性全量)
    - 实施了自动化的数据质量检查"

5. [Options & Recommendation] — 选项与建议
   "现在我们有三个选项:
    A. 维持新时间线和预算, 风险是中
    B. 缩减Phase 1范围, 按时按原预算上线
    C. 暂停重新评估
    我们建议选项B"

6. [Ask] — 需要什么
   "我们需要董事会批准选项B的范围调整, 批准今天就可以继续推进"
```

**关键原则:**
- 坏消息第一时间说, 不要隐瞒
- 带着解决方案来, 不是只带问题来
- 不要过分道歉/防御 — 陈述事实+解决方案+请求决策

#### 4.2 当你被问到不知道怎么回答的问题时

```
错误做法:
❌ 蒙混: "嗯, 这个...大概是...应该...可能..." → 快速失去信任
❌ 撒谎: "没有问题, 一切都在控制之中" → 被发现后信任为零

正确做法:
✅ "这个问题很重要。我现在手头没有确切的数据, 我不愿意给你一个不靠谱的数字。
   我回去确认后今天/明天之内给你书面答复。"
✅ 然后真的在承诺时间内回复。
```

---

### 第五步: 决策请求

#### 5.1 决策请求怎么写

糟糕的决策请求:
"请董事会批准项目继续" (太模糊)
"请董事会支持我们的方案" (支持什么? 钱? 人? 资源?)

好的决策请求:
```
请求董事会批准以下三项:

1. 批准IT战略方向、3年投资框架(总金额$[X]M)
   - 这个框架是指导性的, 每年具体预算会回到董事会单独审批

2. 批准Year 1投资$[Y]M, 用于启动以下工作:
   - [举措1]: $[A]M
   - [举措2]: $[B]M
   - [举措3]: $[C]M

3. 授权CIO在以下范围内拥有决策权(加快执行速度):
   - 单项变更<$[Z]K 且 进度影响<2周
   - 所有超出范围的决定将升级到董事会/SteerCo

建议在[日期]前决策, 以赶上[关键时间窗口, 如供应商年度续约/关键人才招聘窗口]。
```

#### 5.2 有时效性的决策

如果决策真的有时效性, 说清楚为什么:
"我们需要在6月30日前签合同, 因为7月1日供应商年度涨价12%。错过这个窗口, Year 1成本会增加$[X]M。"

## 质量检查
- [ ] 前30秒讲清楚了: 我今天来做什么+请求什么决定
- [ ] 每页PPT标题就是该页的核心信息(不是话题标签)
- [ ] 所有数字有来源, 可以经得起追问
- [ ] 准备了Top 5最可能被问到的问题和答案
- [ ] 如果汇报包含决策请求, 决策是具体且可操作的
- [ ] 会前与关键决策者做了1on1沟通(不在董事会上搞突袭)
- [ ] 附录准备了支撑细节(被问到可以翻)

## 常见陷阱

| 陷阱 | 为什么错 | 正确做法 |
|------|---------|---------|
| Slide太多 | 20页PPT, 讲了40分钟, 听众已经忘了第3页说什么了 | 10-15页, 每页1-2分钟, 总共不超过20分钟 |
| 堆数据不提炼 | "第7页有12个数字, 每个都很重要" — 结果一个都记不住 | 每页只突出1个关键数字, 其他放附录 |
| 念PPT | 高管自己会看, 不需要你念 | 面对听众说话, PPT是视觉辅助, 不是你的提词器 |
| 不提前搞定政治 | 在董事会上第一次让决策者听到你的方案, 然后期待他们当场批准 | 会前1on1沟通, 解决顾虑, 让决策者在会上"公开确认已同意的事" |
| 只在做得好时才汇报 | 出了问题躲着, 等问题爆炸了瞒不住了再汇报 | 坏消息早说, 好消息可以说慢一点 |
| 反复回答同一个人 | 某个董事反复问同一个问题, 你回答了三遍 | 察觉到后, 主动说: "这似乎是你特别关心的点, 会后我单独和你深入聊" |
