# 04 — SOW合同与谈判

## 目标
将Proposal中的承诺转化为有法律约束力的工作说明书(SOW)，保护双方利益，明确交付标准，同时推动签约。

## 前置条件
- Proposal已获客户正面反馈
- 双方对项目范围和方法论基本一致
- 预算已确认(至少量级)

## 输入物
- 获批的Proposal
- 客户合同模板(如客户有)
- 法务审查意见(如有)

## 操作步骤

### Step 1: SOW标准结构

```
1. 项目背景与目标 (Project Background & Objectives)
   [从Proposal执行摘要精炼 — 为什么做这个项目，成功的定义]

2. 工作范围 (Scope of Work)
   2.1 服务内容概述
   2.2 详细工作范围
   2.3 不在范围内的事项 (Out of Scope)
   2.4 假设条件 (Assumptions)

3. 交付物与验收标准 (Deliverables & Acceptance Criteria)
   [每个交付物: 名称+描述+格式+验收标准+验收时限]

4. 项目计划与里程碑 (Timeline & Milestones)
   [含客户依赖的里程碑]

5. 项目团队与职责 (Team & Responsibilities)
   [双方团队+角色+职责+投入比例]

6. 费用与付款安排 (Fees & Payment Schedule)
   [总价/计费方式/付款节点/费用包含与不包含]

7. 变更控制 (Change Control)
   [变更请求的提交流程/评估/审批/费用调整机制]

8. 项目治理 (Governance)
   [SteerCo/周会/升级路径/沟通机制]

9. 条款与条件 (Terms & Conditions)
   [保密/知识产权/不竞争/终止/争议解决/责任限制]

10. 签署页
```

### Step 2: 验收标准的写法 — 这决定项目成不成功

Bad (不可衡量): "完成IT战略规划报告"
Good (可衡量+可验证):

```
交付物: IT战略规划报告

验收标准:
1. 报告覆盖以下章节: 战略背景/现状评估/目标蓝图/差距分析/
   投资组合/3年路线图/治理/财务模型 (共8章)
2. 执行摘要不超过2页，可独立阅读
3. 路线图包含至少3个阶段(Q1-Q2/Q3-Q6/Q7-Q12+)及每阶段里程碑
4. 财务模型包含5年TCO预测和NPV/IRR分析，含乐观/基准/悲观三种情景
5. 成熟度评分有行业对标数据支撑

交付格式: PDF + 可编辑PPT源文件
验收时限: 客户在收到后10个工作日内书面确认或提出修改意见，
         逾期未反馈视为验收通过
修改上限: 1轮重大修改(结构/结论) + 1轮细节修改(措辞/格式)
```

### Step 3: 费用谈判策略

**被客户砍价时的应对:**

```
客户说: "太贵了，隔壁报价只有你们一半"

不要: 马上降价 (这会让你显得一开始在漫天要价)

应该:
第一步(理解): "我理解预算对您很重要。方便让我了解一下他们的范围和我们的一样吗?"
第二步(对齐): "我们在以下方面可能比他们包含更多: [X] [Y] [Z]。
            如果我们调整这些范围，可以在不损失核心价值的前提下优化费用。"
第三步(选项): "我们可以给三个选择:
   选项A (全范围): $X — 覆盖全部需求
   选项B (核心范围): $0.7X — 覆盖最关键部分，其他由客户团队执行
   选项C (轻量诊断+方向建议): $0.3X — 快速诊断+战略方向，不含详细方案"
```

**定价让步的三不原则:**
- 不能在第一次议价就让步
- 不能让价不让东西(每次降价都对应范围调整)
- 不能降超过20%(超过说明原始报价虚高，损害后续合作信誉)

### Step 4: 合同红线 — 这些条款不能妥协

```
绝对不能接受:
  ❌ 无限责任条款 (Unlimited Liability)
     → 必须设Cap, 通常是合同金额的1-2倍
     → 话术: "行业发展标准是责任的合理上限，保护双方"

  ❌ 知识产权完全转让 (Full IP Assignment without limits)
     → 你的方法论/框架/工具是核心资产，不是一次性卖断
     → 话术: "我们为这个项目创建的特定交付物归客户所有，
        但我们带入项目的方法论和工具授权客户使用，所有权归我们"

  ❌ 不合理的付款条件 (如: 项目完成验收后100%付款)
     → 要求: 签约30% + 里程碑40% + 验收30%
     → 话术: "按里程碑付款是行业标准，保护双方对项目节奏的承诺"

  ❌ 无限制的竞业条款 (Non-compete that blocks too much)
     → 可以接受: 项目期间不为直接竞争对手提供同类型服务
     → 不能接受: 项目结束后2年内不得服务任何同行业客户

  ❌ 单方面终止权 (One-sided termination)
     → 双方都应有终止权，并设通知期和已完成工作的支付
```

### Step 5: 推动签约的技巧

```
1. 倒推法:
   "考虑到您希望在Q3看到初步结果，我们建议在[2周后]前完成签约，
   这样项目可以在[3周后]启动，刚好赶上[重要时间节点]。"
   (制造一个温和的时间紧迫感，不强迫)

2. 中间交付物法:
   "在合同走流程的同时，我可以先开始准备项目章程的草案和利益相关者
   访谈清单——这样签约后第一天就能启动，帮您节省2-3周时间。"
   (展示你的投入意愿，建立互惠心理)

3. 风险提示法:
   "坦诚说，这个项目最大的风险不是我们的方案，而是启动时间。
   每延迟一个月，[具体影响和金额]。"
   (从客户利益出发，不是从你的销售指标出发)

4. 小范围先行法:
   如果签约卡在某个点(比如客户不确定范围是否合适):
   "我们可以先签一个2周的快速诊断阶段，产出初步发现后再确定后续范围。
   这样您可以在小额投入下验证我们的方法论和契合度。"
```

## 交付物

- 正式SOW文档(可签署版本)
- 内部定价审批记录
- 谈判策略与底线文档(内部使用)

## 质量检查

- [ ] SOW的每个交付物有明确的验收标准(可衡量)
- [ ] Out of Scope部分和In Scope一样清晰
- [ ] 客户依赖项(如"客户3周内提供X数据")已明确
- [ ] 付款节点与实际交付里程碑挂钩
- [ ] 合同红线条款已审查
- [ ] 法律审查已完成(如需要)
- [ ] 双方Sponsor已确认SOW核心条款

## 常见陷阱

| 陷阱 | 正确做法 |
|------|---------|
| SOW写的太模糊: "提供IT战略咨询服务" | 具体到交付物级别: "产出IT战略规划报告(含X章Y图Z模型)" |
| 为了拿单接受了不合理条款 | 坏条款不会因为你不看就消失——它会在项目出问题时引爆 |
| Out of Scope只写了2-3行 | 写清楚15-20项不包括的内容。客户忘了但理直气壮地说"我以为包含在内" = 范围蔓延的开始 |
| "回头再说"的价格暗示 | 如果现在降了价，客户会记住"原来价格可以谈"——下次照样砍 |
