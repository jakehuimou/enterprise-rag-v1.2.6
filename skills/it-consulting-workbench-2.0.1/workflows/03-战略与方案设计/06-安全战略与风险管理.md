# 安全战略与风险管理 (Cybersecurity Strategy & Risk Management)

## 目标

设计企业安全战略, 基于NIST CSF 2.0框架进行安全成熟度评估, 识别关键风险与控制措施, 制定安全投资路线图。

---

## 前置条件
- IT现状诊断报告已完成(含安全维度)
- 了解客户行业的合规要求(等保/ISO 27001（现行版本）/SOC2/行业监管)
- 了解客户的业务风险偏好

## 输入物
- IT现状诊断报告 (安全架构/安全运维/安全事件历史)
- 行业监管合规清单
- 现有安全投资与工具清单
- IT战略/云战略方向(安全需与架构协同设计)

---

## 操作步骤

### 第一步: 安全风险情境建立 (Context Establishment)

**产出**: 安全情境文档 (Security Context Document)

#### 1.1 识别"皇冠珠宝"

列出客户最重要的5-7个数字资产:

| 资产 | 类型 | 为什么重要 | 被攻破的影响 | 攻击者画像 |
|------|------|----------|------------|----------|
| 客户PII数据 | 数据 | 2000万用户隐私 | 监管罚款+信誉崩塌+集体诉讼 | 黑产/内部人员 |
| 核心交易系统 | 系统 | 每秒处理10万笔交易 | 业务中断, 每分钟损失$X | 勒索软件/APT |
| 核心算法模型 | 知识产权 | 3年研发, 投入$X | 竞争优势丧失 | 商业间谍 |
| ... |

#### 1.2 风险偏好声明

```
我们愿意接受:
- [ ] 低影响的单点故障(如非核心系统宕机<2小时)
- [ ] 低频次的低影响安全事件(如钓鱼邮件<月均5起)

我们不愿意接受:
- [x] 客户数据泄露(无论大小)
- [x] 核心交易系统宕机超过15分钟
- [x] 监管处罚/牌照受影响
- [x] 声誉受损导致客户流失>5%
```

├─────────────────────────────────────────────┤
│  身份安全: SSO + MFA + PIM/PAM + 零信任网络     │
├─────────────────────────────────────────────┤
│  数据安全: 分级分类/加密/脱敏/DLP/审计            │
├─────────────────────────────────────────────┤
│  应用安全: SAST/DAST/SCA/WAF/API安全           │
├─────────────────────────────────────────────┤
│  基础设施安全: 防火墙/IDS/IPS/端点安全/容器安全    │
├─────────────────────────────────────────────┤
│  检测与响应: SIEM + SOAR + EDR + XDR + MDR     │
├─────────────────────────────────────────────┤
│  物理与环境安全: 数据中心/办公/工控物理安全         │
└─────────────────────────────────────────────┘
```

#### 3.2 零信任架构深度设计（基于NIST SP 800-207）

##### 三大核心原则（NIST SP 800-207）
1. **永不信任，始终验证**: 每次访问请求都需重新认证+授权
2. **最小权限**: 仅赋予完成任务所需的最小权限(Just-in-Time + Just-Enough Access)
3. **假设已入侵**: 所有流量加密、微隔离、持续监控

##### 三大技术路径详解
| 路径 | 技术原理 | 代表厂商 | 实施优先级 |
|------|---------|---------|----------|
| **SASE** | 云原生安全+SD-WAN融合 | Zscaler, Netskope, 深信服 | Year1 Q4 |
| **ZTNA** | 应用级加密隧道替代VPN | Zscaler ZPA, Cloudflare Access | Year1 Q2 |
| **微隔离** | 工作负载间精细化访问控制 | Illumio, Akamai Segmentation, VMware NSX, 深信服/山石网科（国产） | Year2 Q2 |

##### 2026零信任趋势
- **AI驱动的自适应策略**: 基于实时风险评分动态调整访问权限
- **身份威胁检测与响应(ITDR)**: 身份系统自身成为攻击面，ITDR成为独立品类
- **OT/IoT零信任框架成熟**: 制造业/能源等OT环境零信任部署指南完善

##### 零信任实施路线图
```
Year 1: 基础建设 — MFA强制+身份治理+设备合规+ZTNA试点
Year 2: 扩展 — 微隔离+数据分级+AI自适应策略
Year 3: 成熟 — 全企业覆盖+AI驱动持续自适应认证
```

##### 零信任关键KPI
| KPI | M6目标 | M12目标 | M24目标 |
|-----|--------|---------|---------|
| MFA覆盖率 | 80% | 100% | 100% |
| 横向移动检测 | <24h | <1h | <5min |
| 异常访问自动阻断 | 30% | 60% | 90% |

##### 零信任三大支柱

1. 身份 = 新边界
   - 永不信任, 始终验证
   - 每次访问都认证+授权
   - 最小权限(Just-in-Time, Just-Enough)
   - 多因素认证(MFA)强制

2. 设备 = 准入前提
   - 设备合规性检查
   - 设备健康度评分
   - 不健康设备自动隔离

3. 网络 = 默认不信任
   - 微分段(Micro-segmentation)
   - 应用间默认不能通信, 显式允许
   - 流量加密(即使在内网)

#### 3.3 OT/IT安全融合 (针对制造业/能源)

```
OT特有安全挑战:
├── 可用性 > 机密性 (IT: 机密性 > 可用性)
├── 系统不能停机打补丁 (需要计划停机窗口)
├── 协议非标准 (Modbus/OPC/Profinet, 无加密)
└── 设备寿命15-20年 (IT设备3-5年)

OT/IT安全融合策略:
├── 工业DMZ: IT和OT之间的安全缓冲区
├── 单向网关: 数据只从OT流到IT, 不允许反向
├── OT网络可视化: 被动流量分析(不主动扫描, 可能造成设备故障)
└── OT专用端点保护: 轻量/不影响实时控制
```

### 第四步: 安全运营设计

#### 4.1 安全运营成熟度

| 层级 | 特征 | 目标 |
|------|------|------|
| L1: 被动 | 出事→响应, 无主动监控 | — |
| L2: 主动 | 有监控, 有流程, 有值班 | MTTD<24小时 |
| L3: 预测 | 威胁情报+狩猎, 自动化响应 | MTTD<1小时, MTTR<4小时 |
| L4: 自适应 | AI驱动+自动化, 持续评估 | MTTD<1分钟, MTTR<30分钟 |

#### 4.2 SOC建设模式选择

| 模式 | 说明 | 适用 | 年成本(参考) |
|------|------|------|------------|
| 自建SOC | 全部自建, 7×24 | 大型企业(>10000人) | $2-5M |
| 混合SOC | 自建安全团队+MDR托管 | 中型企业 | $0.5-2M |
| 托管MDR | 完全外包SOC | 中小企业 | $0.1-0.5M |

#### 4.3 核心安全运营流程

必须正式建立的最低限度安全流程:

1. **事件响应流程 (IRP)**: 检测→分类→遏制→根除→恢复→事后分析
2. **漏洞管理流程**: 发现→评估→优先级→修复→验证
3. **变更管理(安全相关)**: 安全评审→测试→灰度→回退
4. **访问审查流程**: 权限定期审查→异常权限调查→权限回收
5. **安全意识培训**: 入职培训→月度钓鱼测试→年度考核

### 第五步: 供应商/供应链安全管理

#### 5.1 供应商安全分级

| 风险级别 | 定义 | 安全要求 | 示例 |
|---------|------|---------|------|
| **高** | 可访问核心系统/数据 | 现场审计+渗透测试+SOC2 Type II | 核心系统外包运维 |
| **中** | 可访问非核心数据 | 安全问卷+合规认证+年度复评 | 招聘系统SaaS |
| **低** | 无数据访问 | 安全问卷(简化) | 食堂管理SaaS |

#### 5.2 供应商安全审查清单

```
□ 是否有安全认证? (SOC2/ISO27001/等保)
□ 数据存在哪? 出境吗?
□ 谁可以访问我们的数据? 有没有分包?
□ 多久做一次渗透测试? 可以看报告摘要吗?
□ 过去12个月有没有安全事件? 怎么处理的?
□ 发生安全事件, 多久通知我们?
□ 合同到期/终止, 数据怎么销毁?
□ 有BCP/DR吗? 有什么SLA?
```

### 第六步: 安全投资与路线图

#### 6.1 安全投资基准

- 安全支出占IT总支出: 5-10% (金融/政府偏高, 10-15%)
- 人员:工具:服务 ≈ 40:30:30 (世界级安全组织)
- 安全人员占IT总人员: 5-10%

#### 6.2 安全三年路线图

```
Year 1: 止血 (Fix the Basics)
├── 身份安全: MFA强制(全员), SSO, PAM
├── 资产可见性: 清点所有互联网暴露资产
├── 补丁管理流程: 关键漏洞<7天修复
├── EDR部署: 所有终端
├── 安全意识: 全员培训+钓鱼测试

├── 供应链安全正式化
├── 红队演练(每半年1次)
├── SOC成熟度到L2
└── 投入: $[X]M

Year 3: 优化 (Optimize & Automate)
├── AI驱动威胁检测

## 常见陷阱

| 陷阱 | 为什么错 | 正确做法 |
|------|---------|---------|
| "买更多安全工具" | 工具堆叠≠安全, 没有流程和人员运作=昂贵的摆设 | 先定流程和人, 再买工具; 买了的工具必须有人用 |
| 安全=IT安全 | 安全是业务问题, 不是技术问题 | 董事会级别的安全汇报, 用业务语言讲安全风险 |
| 忽视内部威胁 | 大部分安全预算放在防外部攻击, 但内部(有意/无意)泄露占比>30% | 权限最小化+行为异常检测+离职流程安全检查 |
| 安全阻碍业务 | "这个不安全不能做" → 业务绕开IT自己搞 | 安全团队角色转型: 从"No"到"How to do it safely" |
| 纸面合规 | 认证通过了≠安全了, 很多企业拿了ISO27001但实际安全很差 | 合规=最低标准, 真正的安全需要持续改进 |
| 忽视小概率大影响 | "我们不可能是APT目标" → 但你的供应商可能是 | 至少做一次: 最关键3-5个供应商的安全评估 |
