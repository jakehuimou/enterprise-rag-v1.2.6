# 01 — IT战略规划

## 目标
基于诊断发现和客户业务战略，设计一份完整的IT战略规划——明确3-5年IT建设方向、投资重点和实施路线图，使IT成为业务增长的战略资产。

## 前置条件
- 诊断报告已完成并获得客户确认
- 客户业务战略/年度计划已获取
- 客户IT预算范围已了解

## 输入物
- IT现状诊断报告
- 客户业务战略文件 / CEO访谈记录
- 行业趋势研究 + 竞品IT能力对标

---

## 操作步骤

### Step 0: 战略情境分析：数字中国与信创政策影响

在开始战略解码前，先评估三个关键政策维度：

| 政策维度 | 关键问题 | 影响程度 |
|---------|---------|---------|
| 信创要求 | 客户是否在信创替代范围内? | 央国企:高/民企:中 |
| 数据要素× | 客户数据能否成为资产? | 数据密集型:高 |
| 数字化转型考核 | 客户上级/国资委是否有考核? | 央国企:高 |
| 数据出境合规 | 客户是否跨境运营? | 跨国企业:高 |

#### 五力诊断快速摸底（详见references/核心方法论库.md §11）
在战略解码前，用五力模型快速评估客户数字化基线：
- 战略力 [1-5] 数字化战略与业务战略的对齐程度
- 组织力 [1-5] CDO/数字化领导力和人才密度
- 流程力 [1-5] 端到端流程数字化覆盖率
- 技术力 [1-5] 云采用率+API化率
- 数据力 [1-5] 数据驱动决策覆盖率

→ 五力雷达图 → 找到最短板 → 战略重点聚焦

### Step 1: 业务战略解码 — 从业务语言翻译到IT语言

首先将客户的业务战略转化为IT的必须应答:

```
业务战略意图              →     IT战略含义                   →      IT举措
────────────────────────────────────────────────────────────────────────
"3年营收翻倍，进入5个新市场"  →  系统需要支持多国/多语言/多币种/   →  核心系统国际化改造 +
                              多法规, 且能快速复制部署           全球ERP模板 + 云基础设施全球部署

"通过M&A实现非有机增长"     →  被收购公司的IT整合速度和成本       →  M&A IT Playbook +
                              是M&A价值实现的关键                集成架构标准化 + 数据迁移工具

"从卖产品转型为卖服务/订阅"  →  需要IoT/远程监控/订阅计费/         →  IoT平台 + 订阅计费系统 +
                              客户自助门户/数据驱动运维           客户门户 + 数据分析平台

"AI驱动的业务创新"          →  数据是AI的燃料 — 数据治理/质量/     →  数据平台 + MLOps + AI用例
                              标注是前置条件，不是AI本身          Pipeline + AI卓越中心

'信创国产化替代'            →  技术栈安全性+供应链自主可控+        →  全栈国产化适配路线 +
                     减少重复系统                        供应商优化
                     CPU/OS/DB/中间件逐层替代
                     未来合规风险

"降本20%, 提升运营效率"     →  自动化/流程再造/系统整合/          →  RPA+AI自动化 + 应用整合 +
                              减少重复系统                        供应商优化

"提升客户体验和NPS"         →  全渠道体验/个性化/实时/           →  CRM+CDP + 全渠道平台 +
                              数据驱动的客户洞察                  客户数据平台
```

### Step 2: 设计目标能力蓝图 — Business Capability Heatmap

**2.1 识别核心业务能力 (15-25项)**

```
战略级能力 (Competitive Differentiators):
  ├── 产品创新与研发
  ├── 客户洞察与个性化
  ├── 供应链敏捷性
  └── 数据驱动决策

核心运营能力 (Core Operations):
  ├── 采购与供应商管理
  ├── 生产/服务交付
  ├── 销售与渠道管理
  ├── 订单管理
  ├── 财务与会计
  ├── 人力资源
  └── IT与数字化

支撑能力 (Supporting):
  ├── 合规与风险管理
  ├── 法律与知识产权
  └── 企业传播
```

**2.2 能力热度图 (Heatmap: 当前支持程度 vs 业务重要程度)**

```
能力              业务重要性   IT当前支持度   差距    优先级
                   (1-5)       (1-5)
─────────────────────────────────────────────────────
产品创新           5           2              -3     🔴 P0 立即行动
客户洞察与个性化    5           3              -2     🔴 P0 立即行动
供应链敏捷性        4           3              -1     🟡 P1 6个月内
订单管理            4           4              0      🟢 维持
财务与会计          3           3              0      🟢 维持
HR                 2           4              +2     📌 过度投入, 可适当降本
```

### Step 3: 设计目标架构蓝图

**3.1 应用架构目标状态**

按SoR/SoD/SoI三层分类规划:

```
SoR层 (记录型系统 — 追求稳定/标准化/低TCO):
  目标: 核心ERP/HR/财务 — SAP S/4HANA或Oracle Fusion Cloud
  策略: 标准化 → 整合 → 上云 → 流程自动化

SoD层 (差异化系统 — 追求业务适配/敏捷):
  目标: CRM/CDP/电商/供应链决策 — Salesforce + 自研
  策略: 最佳组合(Best-of-Breed) → API-First → 微服务化

SoI层 (创新型系统 — 追求速度/实验):
  目标: AI推荐/预测/Agent — 云原生 + 数据平台
  策略: 快速实验 → 数据驱动 → 快速规模化或快速终止
```

**3.2 应用合理化矩阵 (Application Rationalization)**

```
当前系统     健康度  业务适配度  战略对齐度  建议动作    目标状态
核心ERP      2/5     3/5         4/5        Modernize    → 升级到云版本 + API化
旧CRM        3/5     2/5         2/5        Replace      → 迁移到Salesforce
BI报表       4/5     3/5         3/5        Keep         → 维持, 补充自助分析
电话客服系统  2/5     1/5         1/5        Retire       → 功能并入全渠道客服平台
电商平台      3/5     4/5         5/5        Modernize    → 重新平台化 + 微服务
```

### Step 4: 投资组合设计 — Run/Grow/Transform

```
IT总投资: $XXM/年 (占营收X.X%)

当前分配:
  Run (运维):     $XXM (65%)  
  Grow (增长):    $XXM (22%)  
  Transform (转型): $XXM (13%)  

目标分配 (3年后):
  Run (运维):     $XXM (48%)  ← 通过自动化降低17pp
  Grow (增长):    $XXM (30%)  ← 更多投向业务增长支撑  
  Transform (转型): $XXM (22%) ← AI/数据/现代化

转型路线:
  Year 1: 重点在Run优化 (自动化/系统整合/云迁移 → 释放资金)
  Year 2: 更多投向Grow (业务赋能/数据驱动/敏捷交付)
  Year 3: Transform占比到20%+ (AI创新/新业务模式/生态平台)
```

**投资举措优先级排序 (IPA矩阵: Impact × Feasibility × Alignment):**

```
举措                         战略对齐  业务影响  实施可行性  总优先级  时间
ERP核心现代化                 5         4         3          60        Year 1-2
全渠道客户平台                5         5         4          100       Year 1
AI客户洞察引擎                4         4         3          48        Year 2
IT自动化运营(ChatOps/AIOps)    3         3         5          45        Year 1
数据分析与自助BI平台          4         4         4          64        Year 1-2
云迁移(非核心系统)             3         3         5          45        Year 1
微服务架构改造                3         3         2          18        Year 2-3
```

### Step 6: 治理机制设计

```
IT治理三层结构:

L1: IT投资委员会 (IT Investment Board) — 季度
  成员: CEO/CIO/CFO/BU Heads
  职责: IT战略方向审批 / 大额投资决策 (>$X00K) / 投资组合重平衡

L2: IT架构委员会 (Architecture Review Board) — 月度
  成员: CIO/EA/安全负责人/关键架构师
  职责: 架构标准制定 / 重大技术决策 / 架构例外审批

L3: 项目群/项目治理 — 按项目
  成员: Sponsor/PM/关键利益相关者
  职责: 日常进度/风险/变更决策
```

## 质量检查

- [ ] 每个IT举措都能追溯到业务战略
- [ ] 应用合理化的每个建议动作(退役/维持/改造/替换)有理由和时机
- [ ] 路线图考虑了组织消化能力(不是项目越多越好)
- [ ] Run/Grow/Transform比例有明确的逐年目标
- [ ] 财务模型包含"什么都不做"对比
- [ ] 治理设计明确了决策权归属

## 常见陷阱

| 陷阱 | 正确做法 |
|------|---------|
| IT战略=IT部门的愿望清单 | 从业务战略出发，不是从IT想做什么出发 |
| 路线图塞太满 (20+个项目) | 每波3-5个核心举措，聚焦>全面。消化一个再做一个 |
| 目标架构是"理想乌托邦"(完美但不可达) | 过渡架构比目标架构更重要——客户要知道"一步一步怎么走" |
| 复制同行的战略 | 同样年营收的同行可能需要完全不同的IT战略——情境决定一切 |
