# 02 — AI转型战略

## 目标
帮客户制定AI转型的整体战略——从评估现状，到识别高价值用例，到规划技术平台和人才体系，最终形成可落地的分阶段AI路线图。

## 前置条件
- IT现状诊断(特别是数据维度)已完成
- 客户业务战略已了解
- 客户AI相关投入和项目信息已收集

## 输入物
- 诊断报告(尤其是数据、技术维度)
- 客户AI尝试清单(已完成/正在进行/计划中)
- 行业AI用例对标

---

## 操作步骤

### Step 0: AI宏观定位 — McKinsey AI三波判断

在评估成熟度之前，先帮客户定位当前处于AI价值创造的哪一波：

| 波次 | 如果客户... | 咨询建议 |
|------|-----------|---------|
| 第一波(效率提升) | 刚起步AI，聚焦单点效率用例 | 夯实数据+技术基础，2-3个灯塔项目 |
| 第二波(流程重塑) | 已有AI成功案例，准备扩展 | 端到端流程重构，Agentic AI试点 |
| 第三波(模式创新) | AI成熟度高，追求差异化 | AI原生产品，生态平台，对外输出 |

> ⚠️ GenAI落地鸿沟: 46%企业规模化应用GenAI，但仅9%实现显著商业价值。避免"部署了模型=完成了转型"的陷阱。

### Step 1: AI成熟度评估(AIM²模型) — 先量体温

在给出任何AI建议之前，必须先评估客户当前在哪个阶段:

```
维度            L1(单点实验)   L2(部门推广)   L3(企业运营)   L4(AI原生)   L5(AI生态)
──────────────────────────────────────────────────────────────────────────────
1.战略与领导力    ⬤                                              ○目标
2.组织与人才          ⬤                                          ○目标
3.数据基础        ⬤                                              ○目标
4.技术能力            ⬤                                          ○目标
5.应用场景        ⬤                                              ○目标
6.商业价值            ⬤                                          ○目标

●=当前状态  ○=12个月目标  ☆=24个月目标
```

**给每个维度打分时的关键基准:**

```
战略与领导力:
  L1: AI是IT部门自发行为, 无高管层参与 → 1分
  L2: CIO支持AI, 有预算但无公司级战略 → 2分
  L3: CEO/董事会明确AI战略定位, 企业级预算 → 3分
  L4: 每项业务决策都考虑AI能力, CDO/CAIO直接向CEO汇报 → 4分
  L5: AI成为公司核心竞争力, 对外输出AI能力 → 5分

组织与人才:
  L1: 0-2人兼职做AI → 1分
  L2: 3-10人小团队, 依赖外部 → 2分
  L3: 30+人的AI CoE, 各BU有AI联络人 → 3分
  L4: AI工程师嵌入每个产品/业务团队 → 4分
  L5: 全员AI素养, AI-Native招聘标准 → 5分

数据基础: (这是最常卡住的维度)
  L1: 数据孤岛, 手工整理 → 1分
  L2: 部分数据集中, 有BI → 2分
  L3: 企业数据平台, 数据治理框架, 基本标签体系 → 3分
  L4: Data Products + 联邦治理, 实时数据管道 → 4分
  L5: AI-ready数据生态, 自动化治理 → 5分
```

**关键洞察: 大多数传统企业处于L1-L2之间。直接从L1跳到L3几乎注定失败——必须先夯实数据基础。**

### Step 2: AI机会识别工作坊

**工作坊设计(半天, 15-25人):**

```
参与者: 业务VP×3-5 + IT×3-5 + 数据/AI×2-3 + 产品/创新×2-3

议程:
09:00-09:30  AI能力科普(不是技术深讲, 是"AI现在能做什么"的案例集)
09:30-10:30  分组头脑风暴: "如果AI能帮我们解决3个最大的业务问题,
             这些问题会是什么?" (每个组从不同部门角度出发)
10:30-11:00  整理+投票: 每人3票投给最有价值的idea
11:00-12:00  Top 10 按AI机会画布(AI Canvas)初步展开
12:00-12:30  优先级初排 + 下一步

AI机会画布 (每个idea填一张):
┌────────────────────────────────────────────┐
│ AI机会画布                                  │
├────────────────────────────────────────────┤
│ 业务问题: [要解决的业务问题(不是技术问题)]   │
│ 当前怎么做: [人工方式/现有系统/...]         │
│ AI怎么做: [AI介入的方式: 预测/分类/生成/...]│
│ 数据来源: [需要什么数据, 现在有吗]           │
│ 成功标准: [量化的KPI]                       │
│ 预期难点: [最大的阻碍]                      │
│ 相关用例参考: [行业内外类似案例]             │
└────────────────────────────────────────────┘
```

### Step 3: 用例优先级排序

**RICE+扩展模型评分:**

```
用例评分表:

用例名称: [描述]

维度              权重   评分(1-10)  加权   说明
─────────────────────────────────────────────────────────
Reach (影响范围)     ×1     [__]     [__]   受影响的用户数/交易量
Impact (业务影响)    ×2     [__]     [__]   对营收/成本/体验的影响量级
Confidence (置信度)  ×1.5   [__]     [__]   技术上可行? 数据够吗?
Effort (实施难度↓)   ×1     [__]     [__]   人月估算 + 技术复杂度
Time-to-Value (时间↓)×1.5   [__]     [__]   多久能看到第一版结果?
Data Readiness       ×2     [__]     [__]   所需数据是否存在/质量/可访问
Risk (风险↓)         ×1     [__]     [__]   合规/伦理/模型风险
─────────────────────────────────────────────────────────
加权总分: [___]

优先级: ▢ 立即行动(>60)  ▢ 下一个(45-60)  ▢ 等待时机(30-45)  ▢ 暂搁(<30)
```

**不要平均用力。建议:**
- 选择2-3个高优先级用例作为"灯塔项目"(Lighthouse Projects)
- 每个灯塔项目应在3-6个月内产生可衡量的业务成果
- 选一个"几乎保证成功"的(建立信心) + 一个"如果成功就改变游戏规则"的(突破性)

### Step 4: AI技术架构决策

参见`references/AI与商业转型深度框架.md`获取完整技术决策树。

核心原则:
1. **尽量用现成的**: ChatGPT/Claude Enterprise > 自研LLM (除非数据绝对不能外传)
2. **RAG优先于微调**: 80%的企业AI需求用RAG可以满足
3. **小模型优先**: 在延迟/成本敏感的场景, 小模型+微调 > 大模型
4. **Agent是下一步, 不是第一步**: 先跑通单步骤AI用例, 再做Agent

### Step 5: AI落地路线图

```
Phase 1: Foundation (0-6个月)
  □ AI成熟度基线评估完成
  □ 2-3个灯塔项目启动 (选Quick Win)
  □ 基础数据平台(Data Lakehouse/Catalog) MVP
  □ AI治理框架 1.0 (伦理/偏见/安全/合规)
  □ 核心团队组建: 3-5名ML工程师 + 1名AI产品经理
  □ 第一个AI用例上线 + ROI初步验证

Phase 2: Scale (6-12个月)
  □ 灯塔项目产生可衡量ROI
  □ 从2-3个用例扩展到8-12个
  □ MLOps平台落地 (训练→部署→监控→迭代闭环)  
  □ 数据标注 + 特征工程基础设施
  □ AI CoE扩展到15-20人
  □ 业务部门AI培训 (Citizen Data Scientist项目)

Phase 3: Transform (12-24个月)
  □ AI嵌入核心业务流程和产品
  □ Agentic AI试点 (从简单任务自动化开始)
  □ AI ROI占营收1-3%(具体取决于行业)
  □ 自研模型在某些专业领域超越通用模型
  □ AI能力对外输出 (生态/合作伙伴)
  □ 组织向AI-Native转型 (L4)
```

## 质量检查

- [ ] AI评估6个维度均有评分和证据
- [ ] 每个优先用例都有量化ROI预估(至少量级)
- [ ] 数据就绪度被作为关键约束(不是事后才想)
- [ ] 路线图第一阶段包含"基础设施+数据+治理+用例"四管齐下
- [ ] 考虑了AI伦理/合规/风险管理
- [ ] 不只有"做AI"的投入, 还有"用AI"的变革管理

## 常见陷阱

| 陷阱 | 正确做法 |
|------|---------|
| "我们要做一个AI平台"一上来就建平台 | 平台是第2步, 先用具体用例验证价值 |
| AI团队建在IT部门角落, 跟业务不互动 | AI团队必须嵌入或紧密对接业务团队 |
| 以为"有了ChatGPT企业版就是AI转型" | 通用AI工具=效率10%↑, 行业专用AI=竞争力100%↑ |
| 盲目追大模型, 忽视数据质量 | 模型决定上限, 数据决定下限。垃圾数据→垃圾AI |
| AI策略没有Exit Plan | 每个AI项目都要有Go/No-Go标准, 敢于叫停不work的 |
