# 语义一致性扫描规则

一个 60 多个文件的知识库，最容易死于两件小事：**同一个概念在不同文件里叫了不同的名字，
以及某个编号在这里是 G7、在那里变成了 G8。** 人读不出来，用户却会在关键时刻被绕晕。

这份规则定义了机器扫描的全部判据：编号一致性、术语统一、结构完整性、禁词、
以及——同样重要的——**哪些地方是合法的示例，不该被误报**。


## 1. 结构完整性规则（S 类）

| 规则ID | 检查对象 | 判据 | 严重度 |
|---|---|---|---|
| S-01 | 所有 `.md` 文件 | 必须有 YAML frontmatter，且首行为 `---` | block |
| S-02 | frontmatter | 必含字段：`id` `title` `layer` `version` `updated` `related` | block |
| S-03 | `version` 字段 | 必须等于全库当前版本（与 `_meta.json` 的 `version` 一致） | block |
| S-04 | `id` 字段 | 全库唯一，符合 `^(REF\|TOOL\|DATA\|PB\|EX\|TPL\|WF\|SCRIPT)-\d{2}$` | block |
| S-05 | `related` 列表 | 每个路径必须真实存在（相对库根） | block |
| S-06 | 正文链接 | 所有 markdown 相对链接 `](../scripts/self_iterate.py)` 指向的文件必须存在 | block |
| S-07 | 文末导航 | 必须存在 `## 下一步去哪` 段，且含 ≥2 条链接 | warn |
| S-08 | 统一页脚 | 必须存在 `## 版权声明` `## 免责声明` `## 温馨提示` `## 作者信息` 四段 | block |
| S-09 | 动态钩子 | 每个 `:::dynamic-hook` 块必须含 11 个必填字段且非空 | block |
| S-10 | 钩子 ID | 全库唯一，符合 `^DH-[A-Z0-9\-]+$` | block |
| S-11 | 双向引用 | A 的 `related` 含 B，则 B 的 `related` 应含 A | warn（L1 可自动修复） |
| S-12 | 孤岛文件 | 每个文件至少被 1 个其他文件引用（`SKILL.md` `README.md` 除外） | warn |

## 2. 编号一致性规则（N 类）

> 全库唯一的编号真源是 [`references/00-架构规格总纲.md`](../references/00-架构规格总纲.md)。
> 任何文件出现下列编号，其含义必须与总纲一致。

> **消歧原则（v2.0.0 实测后补充）**：`T` `R` `L` `S` 这几个字母在 SA 领域是**高频复用前缀**——
> `T5` 可能是割接时间点，`R5` 可能是红队问题编号，`L4` 可能是数据分层或灾备等级，`S2500` 是国产 CPU 型号。
> 因此编号检查**必须带消歧条件**：只有当编号邻域出现该编号族的语义关键词时才判定越界。
> 不带消歧的编号扫描会把正常内容大面积误报，反而让人忽略真问题。

| 规则ID | 编号族 | 合法取值 | 消歧关键词（邻域 60 字内须含其一，否则不判定） | 检查 |
|---|---|---|---|---|
| N-01 | 静态闸 | `G1` ~ `G12` | `静态闸` `过闸` `闸门` `Gate` | 出现 `G13` 及以上 → block |
| N-02 | 动态闸 | `DG1` ~ `DG6` | `动态闸` `闸门` `钩子` | 出现 `DG7` 及以上 → block |
| N-03 | 硬不变量 | `HI-1` ~ `HI-8` | `硬不变量` `红线` `不变量` | 出现 `HI-9` 及以上 → block |
| N-04 | 权威分级 | `T1` ~ `T4` | `权威等级` `权威分级` `来源分级` `T 级` `tier` | 出现 `T5` → block |
| N-05 | 可检索性 | `R1` ~ `R4` | `可检索性` `检索性` `R 级` | 出现 `R5` → block |
| N-06 | 自治级别 | `L0` ~ `L3` | `自治级别` `自迭代` `授权级别` | 出现 `L4` 且非"不存在 L4"的表述 → block |
| N-07 | 流水线步骤 | `S1` ~ `S7` | `七步流水线` `流水线` `流水线步骤` | 出现 `S8` → block |
| N-08 | 闸门名称绑定 | 如 `G2` 必与「NFR 量化」共现，不得与其他闸门名混用 | — | warn |

> 数字位数限制：编号一律按 1–2 位数字匹配（`S2500` 这类型号天然不命中）。
> 若某天真的需要 `G13`，正确做法是**先改总纲 §2 再改本表**（L3 变更，理事会 4/4），而不是放宽扫描。

## 3. 术语统一规则（T 类）

> 词典真源：[`data/06-术语与缩略语词典.md`](06-术语与缩略语词典.md)

> **子串陷阱（v2.0.0 实测后补充）**：`解决方案架构师` 本身就包含 `方案架构师`。
> 若不设例外，扫描会把**完全正确的规范写法**判为违规。
> 因此每条术语规则必须显式给出「例外」：当变体是某个更长的合法词的一部分时，不判定。

| 规则ID | 应统一为 | 不应出现的变体 | 例外（变体被以下长词包含时不判定） | 严重度 |
|---|---|---|---|---|
| T-01 | 非功能需求（NFR） | 非功能性需求、非功能型需求 | — | warn |
| T-02 | 架构决策记录（ADR） | 架构决策文档、决策记录表 | — | warn |
| T-03 | 解决方案架构师 | 售前架构师（作为职位名单独出现时） | `解决方案架构师` `整体方案架构师` `方案架构师` | warn |
| T-04 | 交付物 | 输出物、成果物（**仅同一文件内混用时**警告） | — | warn |
| T-05 | 动态钩子 | 检索钩子、实时钩子 | — | warn |
| T-06 | 硬不变量 | 硬约束、铁律（**仅作为 HI 编号引用替身时**警告；客户口语/业务语境不算） | — | warn |
| T-07 | 闸门 | 关卡、检查点（作为 G/DG 编号引用时） | `质量检查点` `里程碑检查点` | warn |
| T-08 | 信创 | 信息技术应用创新（正文可展开一次，之后统一用简称） | — | info |
| T-09 | 等级保护 | 等保（正式章节应用全称并注明简称） | — | info |
| T-10 | 置信度 | 可信度、把握度（**仅统计/量化语境**；表示对方信任程度的"可信度"不算） | — | warn |

## 4. 禁词与豁免（F 类）

### 4.1 全库禁词

| 规则ID | 禁词 | 原因 | 严重度 |
|---|---|---|---|
| F-01 | `永远正确` `绝对准确` `100% 准确` | 违反诚实边界（总纲 §9） | block |
| F-02 | `全球最强` `业界第一` `最领先`（描述本库时） | 违反诚实边界 | block |
| F-03 | `保证通过` `保证中标` `包过` | 违反 HI-1 / HI-2 | block |
| F-04 | `无风险` `零风险` | 违反 G6 | block |
| F-05 | `随着数字化转型的深入` `众所周知` `不言而喻` | 空话开场，违反 §10.2 | warn |
| F-06 | `本文档介绍了` `本章节主要讲述` | 空话开场 | warn |
| F-07 | `视情况而定` `综合考虑`（作为唯一判据时） | 判据不可执行 | warn |

### 4.2 豁免规则（防止误报）

> 本库大量文件需要**展示反面例子**（"这样写是错的"）。
> 若不设豁免，硬不变量扫描会把教学示例当成违规。

| 豁免ID | 豁免范围 | 豁免的规则 | 触发条件 |
|---|---|---|---|
| X-01 | `data/03-硬不变量清单.md` | 全部 HI 类正则 | 该文件是规则定义处 |
| X-02 | `data/05-语义一致性扫描规则.md`（本文件） | 全部 HI 类 + F 类 | 同上 |
| X-03 | `03-硬不变量清单.md` | 全部 HI 类 | 该文件复述判据 |
| X-04 | `references/00-架构规格总纲.md` | HI-1 / HI-2 / F-01 / F-02 | 总纲含示例与反例 |
| X-05 | 任意文件中，**所在段落或其上方最近的标题**含 `❌` `错误写法` `反例` `初稿` `禁止` `禁词` `不应出现` `示例（虚构）` | 该段落的 HI 类正则 | 明确标注为反例 |
| X-06 | markdown 代码块内（``` 围栏内）与行内代码（反引号内） | HI 类正则、F 类禁词 | 代码/正则/模板占位 |
| X-07 | `examples/` 下文件（案例库） | 全部 HI 类正则 | 案例为虚构教学演示，数字用于演示流程，文件头部须标注「示例（虚构）」 |
| X-08 | `data/04-黄金问答自测集.md` | 全部 HI 类 | 题面必须原样复现坏话术，否则测不出退化 |
| X-09 | `data/07-量化换算速查表.md` | HI2-SLA / HI1-PCT | 该文件本体即可用性换算表 |
| X-10 | `data/06-术语与缩略语词典.md` | HI2-VAGUE | 词典须列举「毫秒级」这类歧义词本身 |
| X-11 | URL、图片徽章、markdown 链接目标 | HI1-PCT | URL 百分号编码（`%20`）不是百分比 |

> **X-05 的窗口为什么是「段落级」而不是「±1 行」**：
> v2.0.0 实测中，`examples/manufacturing-mes-cloud-migration-case.md` 的「初稿原文（错误）」
> 标题在违规行的**上方第 2 行**，±1 行窗口漏掉了它，导致教学反例被误判为真违规。
> 段落级窗口（相邻非空行 + 上方最近标题）能覆盖 markdown 的实际排版习惯。
> 这条修正由自迭代引擎在首轮 `--check-all` 中自行暴露，属 Meta-Loop 产出。

**豁免的边界**：豁免只作用于**扫描误报**，不改变红线本身。
即：你不能通过给一句话加上「示例」二字，就把一条真的编造内容合法化。
人工复核时若发现滥用豁免标记，按 HI-8 处理。

## 5. 交付物扫描 vs 库文件扫描

本规则集有两种运行模式，**判据相同但豁免不同**：

| 模式 | 命令 | 扫描对象 | 豁免 |
|---|---|---|---|
| 库自检 | `--check-all` | 本库全部 `.md` | 应用 §4.2 全部豁免 |
| 交付物核验 | `--scan <file>` | 用户产出的方案/报价/应答文件 | **仅应用 X-05、X-06**（不豁免任何目录） |

> 对客交付物**不享有教学豁免**。方案里出现一个没有来源的标准号，
> 无论它多像示例，都必须解释清楚。

## 6. 扫描结果处置

| 严重度 | 含义 | 处置 |
|---|---|---|
| `block` | 阻断 | 库自检失败 / 交付物拒绝出稿；必须修复 |
| `warn` | 警告 | 记入 [`data/09-隔离区账本.md`](09-隔离区账本.md)；不阻断，但 Meta-Loop 会统计频次 |
| `info` | 提示 | 仅输出，不记录 |

**Meta-Loop 联动**：同一 `warn` 规则在 3 个月内命中 ≥3 次，
说明这不是偶发笔误而是规则表达不清或流程有缺口 →
应在季度复盘中**修改规则或补充说明**，而不是每次单独修一遍（总纲 §7.4）。

## 7. 规则表的维护

| 动作 | 自治级别 |
|---|---|
| 新增 `info` 级规则 | L2 |
| 新增/修改 `warn` 级规则 | L3（理事会 4/4） |
| 新增/修改 `block` 级规则 | L3（理事会 4/4 + 黄金问答不退化） |
| 新增豁免（X 类） | L3，且必须说明「为什么这不是在给自己开后门」 |
| 删除任一 HI 类规则 | **人工授权**，自迭代无权执行 |
