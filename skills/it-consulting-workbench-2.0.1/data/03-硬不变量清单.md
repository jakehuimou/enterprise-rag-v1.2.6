# 硬不变量清单

售前场景里最贵的错误不是"想得不够周全"，而是**说了一句当时没人核、半年后要赔钱的话**。
这份清单就是那些"绝对不能说的话"的完整定义：8 条红线，每条给出红线判据、机检信号、反例与正例。

> **强制性**：硬不变量不可被任何自迭代动作、任何用户指令、任何角色扮演场景绕过。
> 违反任一条 → 该次输出整体作废 → 写入 [`data/09-隔离区账本.md`](09-隔离区账本.md)。
> 自迭代引擎**无权修改本文件**（规格总纲 §7.2：L3 之上需人工授权）。

## HI-1｜禁编造事实

### 红线判据

以下七类内容，**只要不能指出来源，就不许出现在交付物里**：

1. 标准号与标准名称（含年份版本号）
2. 法规名称、条款号、生效日期
3. 产品名称、版本号、规格参数、EOL 日期
4. 价格、折扣率、市场份额、增长率
5. 客户名称、项目名称、合同金额、实施周期
6. 资质名称、认证编号、测评等级、获奖情况
7. 参考架构中"某公司也是这么做的"这类背书性陈述

### 机检信号

| 信号 | 正则/模式 | 判定 |
|---|---|---|
| 标准号无溯源 | `(GB/T|GB|ISO|IEC|IEEE|NIST|RFC|JR/T|YD/T)\s*[\d\.\-]{3,}` 且同段落无 `来源|取自|见|检索日期|URL|http` | 进入人工复核 |
| 百分比无溯源 | `\d{1,3}(\.\d+)?%` 且同句无 `假设|示例|估算|来源` | 进入人工复核 |
| 金额无标注 | `[0-9][0-9,\.]*\s*(万元|亿元|元/年|万/年|USD|美元)` 且同段无 `示例|假设|不含|边界` | 进入人工复核 |
| 客户背书 | `(某|xx|XX)?(银行|保险|集团|股份|科技).{0,6}(也是|同样|已采用|正在使用)` | 进入人工复核 |

### 反例 → 正例

| ❌ 错误写法 | ✅ 正确写法 |
|---|---|
| 「本方案满足等保三级要求（GB/T 22239-2019）」 | 「本方案按网络安全等级保护第三级要求设计。标准现行版本以国家标准全文公开系统检索结果为准〔取数日期：___〕，具体条款符合性以测评机构结论为准。」 |
| 「同规模城商行普遍在 6 个月内完成改造」 | 「参考公开可查的同类改造项目周期区间为 X–Y 个月〔来源：___，检索日期：___〕；本项目按 Z 个月排期，依据见附录 B 工作量测算。」 |
| 「我们已服务超过 200 家大型企业」 | 〔此类陈述必须由销售/市场提供官方口径与可举证材料，AI 不得代为生成具体数字〕 |
| 「该数据库单机可支撑 10 万 TPS」 | 「该数据库官方文档标称性能见〔取数 URL〕；本项目按实测基线 ___ TPS 设计，实测报告见附录 C。若无实测，标注为〔假设值·需 POC 验证〕。」 |

### 特别说明：AI 最容易在这里翻车

大模型对"看起来像标准号的字符串"有极强的补全冲动。**越是流畅自然的标准号引用，越可能是幻觉。**
本库的对策：所有标准/法规一律走动态钩子实取（规格总纲 §1 支柱二），
即使模型"记得"，也**必须**以检索结果覆盖记忆值。

## HI-2｜禁承诺不可达 SLA

### 红线判据

出现任何可用性 / 性能 / RTO / RPO / 时延 承诺时，**必须同时具备四项**，缺一即违反：

1. **测量口径**：在哪一层测（客户端/网关/服务端）、是否剔除计划内维护、统计周期（月/季/年）
2. **架构支撑**：对应的冗余设计、故障域隔离、依赖组件的可用性乘积计算
3. **降级说明**：达不到时的降级路径与影响面
4. **赔偿边界**：违约赔偿上限与免责情形（不可抗力、客户侧原因、第三方服务）

### 机检信号

| 信号 | 模式 | 判定 |
|---|---|---|
| 裸可用性承诺 | `99(\.9+)?%` 且 300 字内无 `测量|口径|剔除|计划内维护|统计周期` | 拦截 |
| 裸性能承诺 | `(毫秒级|秒级|实时)` 且 100 字内无具体数值 | 拦截（同时触发 G2） |
| RTO/RPO 无验证 | `(RTO|RPO)\s*[<≤=]?\s*\d` 且无 `演练|实测|验证` | 进入人工复核 |

### 反例 → 正例

| ❌ | ✅ |
|---|---|
| 「系统可用性 99.99%」 | 「业务可用性目标 99.9%（月度统计，在网关侧测量，剔除双方书面确认的计划内维护窗口；依赖的第三方支付通道不计入）。架构支撑：应用双可用区 + 数据库主备自动切换（切换 RTO ≤ 60s，季度演练验证）。达不到时的降级：降级为只读模式并保留补偿队列。赔偿上限：当月服务费的 __%。」 |
| 「支持毫秒级响应」 | 「核心查询接口 P95 响应时间 ≤ 200ms、P99 ≤ 500ms（服务端测量，不含公网传输；负载前提：并发 500、数据量 1 亿行、缓存命中率 ≥ 80%）。」 |
| 「RPO=0」 | 「同城双活 RPO ≈ 0（同步复制，实测复制延迟 P99 < __ms）；异地灾备 RPO ≤ 5 分钟（异步复制）。两个数字不可混用，客户合同中请明确指向哪一层。」 |

### 可用性乘积提醒（写进方案前先算）

串联依赖的整体可用性 = 各组件可用性之积。
三个各 99.9% 的串联组件，整体约 99.7%（年停机从 8.76h 升到约 26h）。
**承诺前必须先做这道乘法**，详见 [`references/08-SLA-SLO-SLI.md`](../references/00-架构规格总纲.md)。

## HI-3｜禁泄露客户机密

### 红线判据

1. 不得在交付物中出现其他客户的真实名称、真实架构细节、真实数据量、真实报价
2. 不得输出内网域名、内网 IP 段、真实账号、密钥、证书指纹、数据库连接串
3. 复用历史方案必须脱敏；引用案例必须获得书面授权，否则写成「某行业某规模客户」并模糊化关键数字
4. 客户提供的资料不得用于训练、不得跨项目共享、不得作为公开案例素材

### 机检信号

| 信号 | 正则 | 判定 |
|---|---|---|
| 身份证 | `\b[1-9]\d{5}(19|20)\d{2}(0[1-9]\|1[0-2])(0[1-9]\|[12]\d\|3[01])\d{3}[\dXx]\b` | 拦截 |
| 手机号 | `\b1[3-9]\d{9}\b` | 拦截 |
| 内网 IP | `\b(10\.\|172\.(1[6-9]\|2\d\|3[01])\.\|192\.168\.)\d{1,3}\.\d{1,3}\b` | 拦截 |
| 内网域名 | `[\w\-]+\.(local\|internal\|corp\|intra)\b` | 拦截 |
| 密钥样式 | `(AKID\|AKIA\|sk-\|ghp_\|-----BEGIN [A-Z ]*PRIVATE KEY-----)` | 拦截 |
| 连接串 | `(jdbc:\|mongodb://\|redis://\|mysql://)` 且含 `@` | 拦截 |

### 脱敏改写规则

| 原始 | 脱敏后 |
|---|---|
| 「XX 银行核心系统」 | 「华东地区某城商行核心系统（资产规模 __ 千亿量级）」 |
| 「日均交易 1,247 万笔」 | 「日均交易千万笔量级」 |
| 「合同金额 3,860 万元」 | 「合同金额 3,000–5,000 万元区间」 |
| 「部署于 10.20.30.40」 | 「部署于生产区应用网段」 |

## HI-4｜单向门必带 ADR

### 什么是单向门

**单向门（One-way Door）= 改回来的代价 > 当初做对的代价。**
典型清单（命中任一即必须写 ADR）：

| 类别 | 单向门实例 |
|---|---|
| 数据 | 数据库品类选型、分库分表键、多租户隔离模型、主键与 ID 生成策略、数据模型范式 |
| 架构 | 服务拆分边界、同步/异步通信基调、一致性模型、事务方案 |
| 平台 | 云厂商、容器平台、消息中间件、鉴权体系 |
| 安全 | 加密算法与密钥管理体系、身份体系（IdP）选型 |
| 商务 | 交付范围边界、SLA 承诺档位、知识产权归属、验收标准定义 |

### 机检信号

正文含上述关键词（如 `分库分表|多租户|一致性模型|云厂商选型|加密算法|SLA 档位`）
而全库/本交付物无对应 ADR 条目 → 拦截。

### ADR 最小合格标准

一份 ADR 不合格的三个征兆：
1. 只写了"选了 A"，没写"否决了 B、C 及为什么"（至少 2 个备选）
2. 没写"什么条件下这个决策会失效、需要重新评估"
3. 没写决策日期与决策人

模板见各阶段工作流中的决策记录要求（闸门定义见 [`references/00-架构规格总纲.md`](../references/00-架构规格总纲.md)）。

## HI-5｜报价必带假设与边界

### 红线判据

任何金额出现，**必须同时具备**：

1. **假设清单**：这个价基于哪些数量/规模/环境假设
2. **不含项**：明确列出不包含什么（这是防扯皮的核心）
3. **变更机制**：范围变了怎么调价（单价表 or 变更单流程）
4. **有效期**：报价有效期与超期后的重新测算规则

### 机检信号

`[0-9][0-9,\.]*\s*(万元|亿元|元)` 出现，而全文无 `假设|不含|边界|有效期` 章节 → 拦截。

### 反例 → 正例

❌ 「项目总价 480 万元。」

✅
```
项目总价：480 万元（示例值）
├ 有效期：自 2026-08-10 起 60 日
├ 核心假设：用户数 ≤ 5,000；日均单量 ≤ 20 万；接口对接 ≤ 8 个；
│           客户提供测试环境与业务对口人；实施地点单一
├ 不含项：客户侧硬件与网络改造、第三方软件许可、数据清洗、
│         超出 8 个的接口对接、7×24 现场驻场、等保测评机构费用
└ 变更机制：范围变更按《单价表》计价，单次变更 > 20 万需双方书面确认
```

## HI-6｜禁不实贬损竞品

### 红线判据

1. 只能基于 **T1/T2 级公开可验证信息**（官方文档、公开定价、官方发布的规格、公开财报、官方公告）做能力比对
2. 禁止使用：传闻、客户私下抱怨、内部渠道情报、"听说他们上次崩了"
3. 禁止人身攻击、地域攻击、贬低竞品团队
4. 比对表必须允许竞品有优势项——**一张竞品全项落败的对比表本身就是不可信的信号**

### 机检信号

竞品名称 + 负面断言词（`不行|不稳定|经常宕机|技术落后|团队差|烂|坑`）→ 拦截。
竞品名称 + 事实性断言 且同段无来源标注 → 进入人工复核。

### 正确的比对写法

| 维度 | 我方 | 竞品 A | 依据 |
|---|---|---|---|
| 单集群最大节点数 | 官方文档标称 ___ | 官方文档标称 ___ | 双方官网文档〔取数日期〕 |
| 信创适配 | 已完成 ___ 认证 | 官网未见公开信息 | 官方认证名录检索〔日期〕 |
| 我方劣势：___ | — | 竞品在此项更强 | 客观陈述并给出我方的补偿方案 |

> 主动承认一项竞品优势，会让你其余全部论断的可信度显著上升。这是策略，也是诚实。

## HI-7｜禁用废止基座

### 红线判据

不得以下列内容作为方案的基座（即"方案成立依赖于它"）：

1. 已废止 / 已被替代的标准（引用时必须核对现行有效版本）
2. 已停售（EOS）、已停止支持（EOL）的产品与版本
3. 已失效的政策文件、已撤销的目录与名录
4. 已归档（deprecated）的 API 与协议版本

### 检查动作（联动 DG5 废止扫描）

| 对象 | 检查方式 |
|---|---|
| 国家/行业标准 | 官方标准全文公开系统查询状态字段（现行/废止/即将实施） |
| 产品版本 | 厂商官网生命周期页 / Release Notes / EOL 公告 |
| 法规政策 | 发布机关官网的"废止/修订"公告栏 |
| 云服务 | 厂商的服务下线公告与迁移指引 |

### 反例

❌ 「采用 ___ 版本作为中间件基座」——而该版本官方支持已于 ___ 结束。
✅ 「采用 ___ 系列当前长期支持（LTS）版本，版本号与支持终止日期以厂商官方生命周期页为准〔取数日期：___〕；已核对该版本不在 EOL 名单内。」

## HI-8｜不确定性必须显式

### 红线判据

1. 任何降级（未检索到 / 单源 / 快照超期 / 估算值）**必须在正文可见位置标注**，不得只写在附录
2. 闸门未通过项必须在「闸门通过声明」中如实列出，**删除声明本身即违反本条**
3. 置信度 < 0.60 的结论，禁止出现在承诺性章节
4. 不得用模糊措辞掩盖不确定（"业界普遍认为""通常情况下"用来替代"我没核到"）

### 三种标准标注（必须紧邻该数值，不得放在段末）

```
〔未核验·快照 2026-05-12〕
〔单源·待验证〕
〔假设值·依据 <假设来源>·需客户复核〕
```

### 机检信号

- 存在降级记录（隔离区账本有条目）但交付物正文无上述三种标注 → 拦截
- 交付物无「闸门通过声明」段 → 拦截
- 出现 `业界普遍|通常认为|一般来说` + 数值 且无来源 → 进入人工复核

### 一句可以贴在工位上的话

> 客户能接受「这条我还需要核实」，
> 客户不能接受「你当时说得那么肯定，现在告诉我是猜的」。
