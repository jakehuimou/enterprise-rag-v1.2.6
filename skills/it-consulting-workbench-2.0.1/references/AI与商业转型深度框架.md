# AI与商业转型深度框架

> 本文档提供AI转型所需的深度方法论, 供相关workflow引用。
> **v1.1.0新增**: McKinsey AI三波、GenAI鸿沟、AI高绩效者画像、数字化转型三阶段深化。

## 1. AIM² 成熟度模型详细评分标准

### L1: 单点实验 (Experimental) — 综合分 1.0-1.9
- **战略**: AI是IT部门的自发行为, 无公司级战略或预算
- **组织**: 0-2人兼职做AI, 高度依赖外部供应商
- **数据**: 数据孤岛, 手工数据准备, 无数据治理
- **技术**: 无ML平台, 单机训练, 手工部署
- **应用**: 1-2个PoC级别项目, 无生产级用例
- **价值**: ROI不清晰, 无法量化AI投入产出

### L2: 部门级推广 (Departmental) — 综合分 2.0-2.9
- **战略**: CIO推动, 有部门级预算, 但未上升到公司战略
- **组织**: 3-10人的AI小团队, 开始与部分业务部门合作
- **数据**: 部分数据集中, 有基本BI平台和数据仓库
- **技术**: 有基础ML平台或使用云AI服务(GPU/ML PaaS)
- **应用**: 1-3个生产级AI用例, ROI可以部分量化
- **价值**: 部分用例产生可衡量的业务效果

### L3: 企业级运营 (Enterprise) — 综合分 3.0-3.9
- **战略**: CEO/董事会明确AI战略, 企业级AI预算, CDO/CAIO任命
- **组织**: AI CoE 30+人, 各BU有AI联络人, MLOps工程师
- **数据**: 企业数据平台(Lakehouse), 数据治理框架, 特征工程平台
- **技术**: 完整MLOps平台, 模型工厂, AI服务目录
- **应用**: 10+个生产级用例, 覆盖多个业务领域, 每个有明确ROI
- **价值**: AI ROI占营收可量化, 季度AI价值报告

### L4: AI原生组织 (AI-Native) — 综合分 4.0-4.9
- **战略**: AI驱动核心业务决策和产品创新, AI能力=核心竞争力
- **组织**: AI工程师嵌入每个产品/业务团队, 全员AI素养评估
- **数据**: Data Products + 联邦治理, 实时数据管道, 语义层
- **技术**: Agentic AI平台, 自动化ML/LLMOps, 自主治理
- **应用**: AI嵌入>50%的核心业务流程, Agentic AI进入操作层
- **价值**: AI收入占比>10%总收入(因行业而异)

### L5: AI原生生态 (AI-Ecosystem) — 综合分 5.0
- **战略**: AI能力对外输出, 构建产业/生态平台
- **组织**: AI-Native招聘标准, AI文化=企业DNA
- **数据**: 数据/AI能力即服务(DaaS/AIaaS), 数据飞轮效应
- **技术**: 多Agent自主协作网络, AI自我优化基础设施
- **应用**: AI创造新商业模式/新收入来源/新产品线
- **价值**: 行业AI标准制定者, AI生态收益>核心业务收益(部分企业)

## 1.5 McKinsey AI价值创造三波浪潮

| 波次 | 时间 | 特征 | 价值 |
|------|------|------|------|
| 第一波: 技术赋能 | 2023-2026 | LLM/Copilot/自动化 | 效率↑15-40%，成本降低 |
| 第二波: 流程重塑 | 2025-2028 | AI Agent/多模态/领域模型 | 产品/服务AI化，新商业模式 |
| 第三波: 模式创新 | 2027-2030+ | AGI雏形/人机协作/制度变革 | 行业边界重塑，新市场诞生 |

> 注：以上时间窗与 GenAI 数据口径以 SKILL.md 主文「McKinsey AI 价值创造三波浪潮」为**单一事实源**（已于 2026-07 对齐；旧口径 2022-2024/2024-2027 为历史版本，不再使用）。

### GenAI落地鸿沟
**全漏斗**：88%企业已使用AI → 46%规模化应用GenAI → 仅9%实现显著商业价值。差距37pp。（与 SKILL.md 对齐，McKinsey 2025-2026，截至2025全年）
三大根因: 数据就绪度(62%) > 人才短缺(55%) > 治理缺失(48%)

### AI高绩效者六大画像
| 维度 | 高绩效者 | 落后者 |
|------|---------|--------|
| 战略 | CEO级AI议程 | IT部门自发行为 |
| 投资 | AI预算>15%IT总支出 | AI预算<5% |
| 组织 | AI嵌入BU | 独立实验室 |
| 数据 | 数据产品+实时管道 | 数据孤岛 |
| 技术 | MLOps L3+ | 手工部署 |
| 文化 | Fail Fast | 怕失败/盲目追热点 |

## 1.6 数字化转型三阶段深化

| 阶段 | 特征 | 典型工作 | 关键指标 |
|------|------|---------|---------|
| 1.0 信息化 | 纸质→电子 | ERP/OA/CRM上线 | 系统覆盖率>80% |
| 2.0 数字化 | 数据驱动 | 数据中台/AI/全渠道 | 数据驱动决策>50% |
| 3.0 智能化 | AI原生 | Agentic AI/自主决策 | AI贡献收入>10% |

跃迁陷阱: 从1.0跳3.0(跳过数据基础)、以为"买系统=转型完成"、忽视组织文化变革


## 2. 5D AI落地框架 (Thoughtworks)

任何AI项目成功需要五个维度同时发力:

### D1: AI素养 (AI Literacy)
- **全员**: 理解AI能做什么/不能做什么/如何提需求
- **管理者**: 理解AI投资逻辑, 不做"AI旅游"
- **技术人员**: 持续学习, 不被工具替代
- ⚠️ 仅20%的开发者能持续有效使用AI编程工具

### D2: 强工程实践 (Strong Engineering)
- 代码质量、测试、架构纪律不因AI而降低
- MLOps/LLMOps成熟度是规模化前提
- 可观测性/可回滚/可审计

### D3: 内部拥护者 (Internal Champions)
- 培养跨层级的AI倡导者
- 自下而上创新 + 自上而下支持
- 庆祝小胜利, 建立正向飞轮

### D4: 完善治理 (Sound Governance)
- 实验室→雷达→结构化监督
- 模型风险管理(偏见/幻觉/安全)
- AI法案对齐(EU AI Act/中国生成式AI管理办法)

### D5: 聚焦实验 (Focused Experimentation)
- 用例驱动(不是技术驱动)
- 最小可行模型(MVM)
- 每个实验有明确的Go/No-Go标准

## 3. Agentic AI企业落地框架

### 三层架构 (Accenture Hive Model)

```
L3 — 编排层 (Orchestrator Agents)
  ├── 跨部门复杂决策协调
  ├── 多Agent任务编排与冲突解决
  └── 人工审批节点集成

L2 — 监督层 (Super Agents)
  ├── 领域流程监督与目标达成
  ├── 异常检测与人工升级
  └── KPI: 流程完成率/准确率/人工升级率

L1 — 执行层 (Utility Agents)
  ├── 单一明确任务的自动化
  └── KPI: 任务完成率/处理时间/错误率
```

### 落地路线图
- **M1-3**: 选3-5个L1高价值低风险场景, 建立Agent治理框架
- **M4-6**: L1上线+迭代, 选1-2个L2场景PoC
- **M7-12**: L2规模化, Agent运营仪表盘
- **M13-18**: 评估L3编排层可行性

### Agent治理核心
- **身份**: 每个Agent有唯一身份标识, 绑定权限
- **边界**: "Agent能做什么/绝对不能做什么"的显性规则
- **审计**: 所有Agent决策可追溯
- **指标**: 决策吞吐量/决策接受率/人工干预率/错误率

## 4. AI技术架构决策树

```
需求: 我要用AI解决[业务问题]
│
├── 问题是标准化的(客服/翻译/代码/写作)?
│   └── 直接使用通用模型API (ChatGPT/Claude/Gemini)
│       ├── 需要企业级安全? → Enterprise版本
│       └── 需要引用内部知识? → + RAG
│
├── 问题需要引用大量企业内部知识?
│   └── RAG架构 (LangChain/LlamaIndex/Dify)
│       ├── 知识量<1万文档 → 简单RAG (Embedding + Vector Search)
│       ├── 知识量>1万文档 + 结构化查询 → Agentic RAG
│       └── 对准确性要求极高 → + Fine-tuning
│
├── 问题需要学习特定风格/领域语言?
│   └── Fine-tuning (微调)
│       ├── 数据<1000条 → 不推荐微调(样本不足)
│       ├── 数据1000-1万条 → LoRA/QLoRA
│       └── 数据>10万条 + 自研需求 → Full Fine-tuning
│
├── 问题需要多步自主执行?
│   └── Agent框架 (LangGraph/CrewAI/AutoGen)
│
└── 问题涉及核心IP/绝对隐私?
    └── 自研模型 / 私有化部署开源模型
        ├── 成本敏感 → 小模型(Llama/Mistral/Qwen) + LoRA
        └── 不在乎成本 → 大模型 + Full Fine-tuning
```

## 5. AI用例优先级评分 (RICE+ Extended)

```
用例: [名称]

维度               权重   评分(1-10)   说明
────────────────────────────────────────────
Reach (影响范围)     ×1     [__]        受影响用户数/交易量/收入占比
Impact (业务影响)    ×2     [__]        对营收/成本/体验/风险的影响
Confidence (置信度)  ×1.5   [__]        技术上可行? 数据够吗? 有类似案例?
Effort (难度↓)       ×1     [__]        人月 + 基础设施成本
Time-to-Value (速度)  ×1.5  [__]        多久产生第一个可衡量成果?
Data Readiness       ×2     [__]        所需数据的可用性/质量/合规
Risk Level (风险↓)   ×1     [__]        合规/伦理/模型风险/组织阻力

加权总分: [___]

>60:  立即行动 (Lighthouse项目)
45-60: 下一个 (Q2-Q3启动)
30-45: 等待时机 (依赖其他条件)
<30:  暂搁
```

## 6. AI实施反模式

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| "先建AI平台" | 没有用例的平台=没有顾客的商场 | 先用1-2个用例跑通端到端, 再抽象出平台 |
| "招10个数据科学家" | 数据科学家没有数据工程师和数据=巧妇难为无米之炊 | 数据工程师:ML工程师:数据科学家=3:2:1 |
| "做个ChatGPT企业版" | 通用AI=效率提升~10%, 行业专用AI=竞争力提升~100% | 把80%精力放在场景+数据+集成 |
| "模型越大越好" | 当前模型分层路由实践（已于2026-07更新）：轻量模型(GPT-4o-mini/Claude Haiku/Qwen-Flash)处理简单任务，大模型(GPT-4.1/Claude Sonnet/DeepSeek-R1)处理复杂推理 | 分级策略: 按任务复杂度路由到合适模型层，平衡成本与效果；旧版GPT-3.5/GPT-4对比已过时 |
| 忽视模型监控 | 模型上线=故事的开始, 不是结束 | Day 1: 数据漂移/模型衰减/偏见/成本监控上线 |
